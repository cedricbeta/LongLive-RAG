# Feedback v2 四例实际结果

排队实验已经结束：3 例完整完成，Clara 衣服案例触发 5,400 秒上限。冻结源码、输入和归档对照哈希复核通过。没有在查看结果后重跑或替换案例。

**结论：未获得修复质量提升；Iris 的最终交付还失去了 v1 已接受的修复。** 三个完成案例的 v2 最终文件均与各自 baseline 字节相同。无需修复的对照保持不动属于预期结果；另外两例表示修复没有被接受、交付退回原片。

| 案例 | 原版 | v1 | v2 |
| --- | --- | --- | --- |
| Iris 头发 ns090 | 3 次重画，2 次修复被接受，无未解决镜头 | 4 次重画，1 次修复被接受，未解决镜头索引 2、5 | 7 次重画，0 次被接受；全部 6 个镜头未解决，最终等于 baseline |
| Clara 衣服 ns310 | 1 次重画、1 次被接受，54.7 分钟完成 | 1 次重画、1 次被接受，53.6 分钟完成 | 已完成 6 次重画均未通过；第 4 镜头检查阶段达到 90 分钟上限，无完整最终结果 |
| 缺失 Luna ns020 | 3 次重画，未补回 | 3 次重画，未补回 | 2 次重画后停止，仍未补回；最终与 baseline、原版、v1 相同 |
| 无需修复对照 ns130 | 0 次编辑 | 0 次编辑 | 0 次编辑；与 baseline、原版、v1 相同 |

以上是现有裁判和交付记录，不是独立人工画质评分。Iris 示例帧可见原版/v1 的头发改色，而 v2 保持 baseline 的深色头发。跨版本后续镜头的姿态也会不同，不能把某一帧差异全归因于本镜头的 mask。

## 接口改动确实生效，但没有转化为合格修复

- Iris 第 3 镜头依次使用扩大范围、同范围重新抽样、降低阈值后的范围。第三轮确实改变了 mask，不再是三次完全相同的操作。三轮都未通过头发颜色检查。
- Iris 第 2、第 4 镜头以及 Clara 部分镜头，模型仍重复原参数；程序退回后模型没有给出合法的新方案，最终以 `planner_error` 结束该镜头。这是策略校验失败，不是 GPU 或推理服务崩溃。
- Luna 在相同整镜头方案失败两次后，第三轮重复被拦，模型选择停止。少浪费一次渲染，但目标没有完成。

## 值得优先复核的失败链

Iris 第 1 镜头重画后的截图投票为 `[true, false, true]`。负票包含明确的衣服冲突：要求苔绿外套，实际仍为深蓝 polo。由于首次身份参照要求更严格，结果为 `reject_identity_reference_low_confidence`；v2 把这个理由归为“证据不足”，立即停止。

这说明“低置信度”这个总标签可能同时包着真实的可见缺陷，不能机械地一律停下。这次最初的成功修复未建立，后续是在不同于 v1 的父版本上继续尝试，因此后续失败不能直接证明“扩大范围本身更差”。同时，这次修改了区域、caption 和停止策略，仍不是单因素实验。

下一步应先针对原版已经成功的 Iris/Clara 第 1 镜头，固定输入与随机种子，分别只改变范围、只改变 caption、只改变停止策略，找出成功丢失在哪一步。当前结果不支持继续扩大双模型循环的计算预算。
