# Feedback repair v1：原因复核

在结果汇总之后，对实际规划输入、动作、mask 张量和验收日志进行只读复核。以下区分已观察到的事实与尚待消融验证的推断；没有修改冻结实验或重跑模型。

## 1. 规划输入带着现成答案，实际搜索范围很小

五个完成案例共调用规划器 10 次。每次 `packet.options` 都只有一个可编辑区域方案，另外允许 stop；属性动作可选四种 sigma，缺席动作只能选整镜头 sigma 1.0。

全部 10 次的 reason 都复制了该默认动作的 reason 标签；6 次 caption 也与默认动作原文相同。全部选择 sigma 1.0。ns090 第 3 镜头连续三轮 caption 和强度完全相同；ns050 前瞻拒绝前后两轮亦相同。

可以确认模型没有展开有效的参数探索。默认选项内附完整 caption、sigma、reason 可能造成照抄倾向，这是推断，需去掉默认答案再比较。JSON 字段 `change_from_previous` 只要求非空，没有检验实际参数是否改变、是否回应失败证据。

## 2. 固定区域是额外的算法变化

新版每次从原父版本提供的固定 mask 出发；旧版可以从最新失败候选重新提取 mask，再进行下一次父版本重放。

对 ns090 第 3 镜头实际张量核对，而非比较含元数据的文件哈希：

- 第一次编辑：两版 mask 张量完全相同，覆盖率均约 1.289%。
- 第二次编辑：原版区域覆盖率约 1.481%，新版仍约 1.289%；以 0.35 二值化后的区域交并比约 0.562。

因此第二轮已经不只是在比较“是否增加规划模型”。固定区域限制了模型调整修复范围的能力，是新版未通过验收的重要嫌疑因素，但没有单因素实验就不能断定它独自导致了失败。旧版从候选获得的区域用于父版本重放也不天然正确，应检查对齐关系。

## 3. 不确定性与画面缺陷没有得到不同处理

ns050 新版第一次候选的当前镜头通过理由是 `accept_with_unknown_assignment`；目标 Dario 的出场其实仍是 unknown，没有被确认找回。后续拒绝来自人数检查从 satisfied 变为 unknown，即丢失原有证据，并非明确测得新缺陷。

反馈正确标记为 `insufficient_evidence`，但执行路径仍只有重画或停止，没有补帧、重新定位、复核角色的动作。第二轮重复同一个 caption，并把“Dario 现在已出现”写进 change_from_previous，未回应实际的不确定性。

这说明还需要两项区分：原片可以带未知项交付，不代表一次以补人为目标的修复可以在目标仍未知时宣告局部成功；检查不清应优先补证据，不应自动变成重画指令。

## 4. 验收差异不是连续画质差值

ns090 第二轮的原版结果只有一张 crop 被颜色检查否决，新版有两张被否决，触发不同聚合结论。已有日志出现接近颜色冲突阈值的值，例如 51%、53%、56%。这些支持保守的验收判断，但不能仅从接受数推出显著的人眼质量差异。

## 5. 执行器能力仍需单独测

ns020 的六次编辑（两版各三次）都未被识别到 Luna。现有方案主要通过文本和整镜头重采样补人，没有新增显式的角色位置/参照控制。该结果提示执行器控制能力可能是瓶颈，尚不足以证明文本路径绝对补不回来，也不能据此确认某一种内部状态机制是根因。

## 修正顺序

先恢复可比较的区域策略，在固定输入、种子和验收下做小范围参数对照；查明现有动作能否生成合格候选。再给规划者真实可选择的动作，减少默认答案的引导，并检查所提调整是否具体回应失败。为 evidence unknown 接独立复核路径，同时要求本轮修复目标必须获得明确成功证据。最后再评估是否需要新的生成控制能力。

责任归因：本轮首先暴露的是 v1 动作接口、区域策略和反馈处理的限制，不能简单归因于模型不够聪明，或据此否定双角色协作。
