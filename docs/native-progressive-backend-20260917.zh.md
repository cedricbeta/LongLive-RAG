# 官方 LongLive-RAG 渐进事务后端：实现与接入审计

这是开发阶段的软件与证据绑定检查，不是新增的修复效果实验。官方生成器已接入共享 `ProgressiveShotSession` 的后端接口；自动诊断/定位的完整在线接入、可靠验收和新的真实闭环试验仍未完成。

## 已实现的执行路径

`adapters/official_longlive_rag/progressive_backend.py` 使用原有官方候选准备器、GPU 资源监督器和实际父分支工程审计。准备器由指定的生成环境 Python 启动，校验全部配对资产；随后监督器生成整片，再检查前缀、mask 外 latent、原始文本条件恢复、随机数、KV 游标、AE 和记忆记录。新候选不会自动覆盖当前最好分支。已有尝试的配置和记录不能被覆盖重跑。

每个分支绑定视频、原始 latent、配置、时间表、切换记录、检索日志、运行状态和审计文件的实际 SHA-256。快照恢复会重新检查这些内容。这里的“状态恢复”是选择不可变父产物并在下一次生成中完整重建，不是序列化或恢复驻留 GPU 的 KV/RNG 快照，不能宣称实时流式优势。

当前最好、原始分支与完整检查分支分别记录。部分改善进入下一轮父分支，但不产生可信身份参考；失败子分支进入隔离状态。后端要求所有创作镜头都有对应的通过记录，才填写完整检查分支指针，且这个指针仅表示配置中的开发检查器通过。新修复会使继承的后续镜头通过记录失效。未解决镜头仍保留在结果中。

共享会话已支持 native mask 的时间坐标和真实 tensor 哈希，保留本地 5B 路径。失败后的合法区域预览使用官方连续 VAE 对应的导出帧。后续成对保护现在收到本轮的明确目标要求，并按实体/部位/方面/期望值区分同一目标与其他要求；目标 ID 中的镜头编号不会造成错误区分。

## 验证与限制

导出仓库运行了 111 项测试及 9 个子测试。其中 20 项为新的官方后端合成事务测试，涵盖部分保留、后续退化/unknown、旧父 mask 拒绝、失败回退、状态/证据篡改、完整分支指针、准备—生成—审计的调用顺序、资源拒绝和禁止覆盖。合成渲染器与合成验收只检验控制逻辑，不是视频质量证据。

另在真实官方 Iris 父视频、候选、latent、mask 和旧诊断上运行归档事务接入检查。它重新执行工程审计、逐帧校验诊断来源，并调用真实候选准备 CLI 校验全部 12 项资产与首轮动作。生成监督器没有启动。事务的一个渲染调用槽由严格匹配父版本/区域/提示词/种子的历史候选提供；新增视频和 VLM 调用均为零。

接入检查发现范围不兼容：共享固定配方把衣物颜色和衣物类型两项已知失败一起作为目标，而旧官方保护探针只以颜色为目标。旧保护判断不能当作新输入包的判断。程序记录 `archived_guard_target_scope_mismatch`，将当前验收视为证据不足，停止并选择原视频；没有保留候选，没有进入后续验收，也没有把先前的有问题检查器重新作为可信结论。前两个无对应归档诊断的镜头明确记为 unknown，没有伪造通过标签。

第一次接入探针由于测试用历史动作遗漏必需 reason 字段而失败，发生于渲染前。错误记录、当时源码及耗时均保留。修正后各版本另建目录；旧失败未覆盖。

## 距离实际闭环的差距

后端可以调用真实生成器，但本轮实际事务采用归档候选检索，并未通过生产执行器完成新的生成。完整自动流程还需要把脚本约束编译、当前父分支分割和成对检查器直接接到官方时间坐标，冻结新的开发试验，并保留其所有失败和成本。现有 Qwen 保护检查仍不可靠，Iris 面部证据仍为 unknown。后端接入不解决这些验收问题，也不证明反馈优于固定重试。

同预算对照、独立留出、多系统验证、独立评估与真实匿名人工比较仍未完成。当前材料不满足 submission-ready。
