# 名字候选与离线窗口：开发记录

本次新增可选 `names_v6` 协议，让模型对程序提取的每个名字候选明确分类。它解决了当前 Iris 开发脚本的空人物表，但另一脚本出现新的出场矛盾。通过程序检查不等于语义准确，也不证明纠错有效。

程序从原始脚本的大写词提取最多 32 个候选，固定名字、字符偏移、全部出现位置及候选 ID。普通句首词和地点也保留，不能由程序直接当作人物或删除。模型必须逐 ID 返回人物/非人物/歧义分类，并声明每个镜头的出场情况；非人物与出场相矛盾时立即拒绝。人物外观仍由 v5 的不可修改物理短语和归属协议生成，最多两次文本调用，没有人工补属性或纠正重试。

| 同一组已暴露开发脚本 | v5 + schema 消息 | v6 名字候选 + schema 消息 |
|---|---|---|
| ns090，Iris | 空人物表，未就绪 | 程序就绪，1 人 |
| ns310，Clara/Miles | 程序就绪，2 人 | 程序就绪，2 人 |
| ns050，四个人物 | 程序就绪，4 人 | 执行拒绝：非人物却声明出场 |

v6 共执行 **5 次真实文本调用、148.84 秒 worker 时间**。ns050 将 `The` 和 `They` 判为非人物，同时在部分镜头声明 required；程序在外观归属前停止，没有归一化或偷偷重跑。Iris 只得到四个原文属性：第二镜头起的 curly/red hair、第三镜头起的 moss green/coat。没有添加年龄、体型或其他隐藏要求。Miles 仍没有未指定的发色。原始回答、冻结源码、配置和失败均见[完整结果](../results/typed_script_compiler_v6_development/run/results.json)，可重建的[汇总](../results/name_candidate_contracts/development_summary.json)附输入哈希。

这只是顺序开发比较。有限英语大写规则不保证覆盖小写名字、别名或远距离指代；强制分类也不能保证分类正确。`semantically_validated` 保持 false。

v5 共用归属代码的提取另经离线重放检查：三个历史案例的原始请求文本、schema 和编译输出均保持相同，没有新增模型调用。第一次审计误用排序后的缓存字典导致请求字节断言失败；该失败也保留。正确重放从原始模型回答字符串恢复键顺序。这个发现说明语义相同的 JSON 字典仍可能生成不同的后续提示词字节；没有改写历史缓存或共享客户端。

## 后续依赖和离线起点

发现并修复一个会遗漏后续检查的程序问题：原生实体使用 `shots=()` 加显式 `presence`，旧依赖计算只读取 `shots`。现在后续依赖取两者的并集，明确出场和歧义出场都保留；当前及过去镜头不加入。有限前瞻仍按时间选择，不把歧义当作不出场。测试贯穿原生实体转换、依赖提取及运行时的前瞻选择。

首次 Iris 第三镜头试运行在 **54.13 秒**后因共享会话要求按顺序交付而停止。完成两次文本编译调用，尚未调用视觉诊断或生成器。[原始失败](../results/native_iris_names_v6/run/status.json)及其源码完整保留。

新增明确的离线窗口入口只接受保存完好的、已完成的原生父视频，并重新校验视频、latent、配置、时间表、切换和检索记录的哈希。跳过的前缀不加入已交付镜头，不增加可信记忆或身份参考。开始后仍须按顺序处理当前窗口；全片通过仍要求全部原始镜头都有通过记录。普通生成会话继续保留原有顺序限制。

导出实现通过 [222 项测试和 11 项子测试](../results/name_candidate_contracts/exported_tests.txt)。测试验证上述程序边界和回退逻辑，不能证明视频质量或模型可靠性。先前 189 项、215 项测试记录保留，未改写为新源码的结果。

第三镜头的自动诊断认为衣服颜色和种类冲突，头发颜色与发型满足。运行时实际记录的未来依赖为 `[3,4,5]`，说明 presence 已进入依赖路径，但这不表示这些镜头均被检查。原生动作绑定 `[81,121)` 的 40 个 latent、原始父视频和原始 latent 哈希，使用自动衣服区域及原文属性，强度 1、种子 4243。

![本次实际使用的自动衣服区域](../artifacts/native_iris_names_v6_window/automatic_garment_mask.png)

预览对应第 320、400、476 个导出帧；红色为真实执行的四帧并集区域。平均覆盖约 17.94%，后两幅可见部分手臂也在区域内。该图没有人工像素真值，零估计保护重叠不能证明边界准确。预览未用于修改这次已冻结的动作，也未将此前的 SAM2 部位传播方案加入首次配方。


## 实际原生候选与回退

修正离线入口后的冻结运行完成，worker 用时 **1170.11 秒**，生成一个 60 秒原生候选，生成器耗时 **793.67 秒**。总计 21 次真实模型调用：2 次编译、12 次人物枚举/归属、6 次单帧属性检查、1 次联合复核。生成器时间和各调用时间包含在 worker 时间内，不能再次相加。独占检查器服务从启动到退出标记为 1220.19 秒，包括加载和空闲，不是 GPU kernel 时间。前一次入口失败的 54.13 秒及两次编译调用另行保留，不从成本中隐藏。

[工程审计](../results/native_iris_names_v6_window/run/backend/candidate_0001_shot02_attempt1/audit.json)验证 81 个前缀 latent 精确相同，修复范围 `[81,121)` 内掩码外 latent 精确相同；40 个编辑 latent、120 个后续 latent 均发生变化。真实 KV/检索状态随新后缀重建，执行 56 次额外去噪调用。四个可选掩码均通过父状态绑定和逐元素投影审计，但只执行首次通用方案；其他选项不是生成对照。

候选的两项衣服原子要求，以及包含它们的外观汇总项，从 violated 变成 unknown；另四项保持 satisfied。汇总项与原子项有包含关系，不能说出现了三个独立衣服缺陷。候选单帧回答对衣服为 fail/pass/pass，联合复核则对两项都返回 fail，因此冻结冲突规则保留 unknown。还发现一条[原始回答内部矛盾](../results/native_iris_names_v6_window/checker_conflicts.json)：衣服类型的 status 为 pass，解释却明确说不符合 coat 要求。这是模型可靠性故障，不是人工标签。

当前目标没有得到确认改善，运行以 `insufficient_evidence` 停止，**保留改善为 0，交付原始父视频**。成对视觉保护调用为 0，实际未来检查为 0；不能把请求的前瞻 1 写成已检查 1。original/current-best 均为 `native-0000`，完整通过分支为空；隔离区保留父、候选两个观察，可信记忆及身份参考为空，无不可见记忆泄漏。
