## 评分协议

- 使用当前本地 NarraStream 实现与 local_qwen3vl8b 配置，全部 API 指向独立本地服务；不调用付费云端。
- 仍是 Qwen3-VL-8B 迭代裁判，而非论文的 30B VLM / 27B planner；与控制器同模型家族，不宣称跨模型独立验证。
- 评分进程只读提示、视频，不读取控制器接受/回退判决，不按结果筛选案例。
- API temperature=0，显式发送 seed=0；完整请求（含图片内容、提示、模型、采样参数）进入指纹。
- 主比较共享内容寻址的 API 响应缓存：完全相同的输入得到同一份裁判响应。
- 缓存中保留原始响应及图片内容哈希，单独记录 API 耗时、缓存命中、截断、请求异常。
- 每次评估使用全新 sample-ID 缓存目录，冻结输入视频、切段文件、提示与评估代码 SHA-256；结束后复核。
- A/B/旧 C 的现有切段均检查为 33 场景、六段、每段 64 帧、24 FPS；C 交付视频必须完整 384 帧才切段。
- 指标本身的默认分与回落逻辑未改。`audit.json` 报告可观察的 fallback 证据，但不宣称覆盖所有静默回落；原始日志仍需审计。
- C 如缺场景或生成失败，队列停止，不把失败项悄悄从 33 的分母中删除。

固定噪声样本是 A 的索引 `[0, 6, 12, 18, 24, 30]`，不根据分数选样。
每次使用新的 API、planner、实体抽取与 metric 缓存空间，运行 CAC、CLC、EG、VLM 四项，共三次。
因此三次不是读取同一份缓存的假重复。报告逐样本三次分数及极差；这是小样本噪声诊断，不是准确性认证。

自动输出 `evaluation33/comparison.md` 和 `comparison.json`：
全指标及组分数、各方法相对 A 的逐场景配对 bootstrap 区间（2000 次、固定 RNG seed 0）、裁判重复分数。
这仅估计单个生成 seed 下的场景抽样不确定性，不冒充多 seed 鲁棒性。

## 本轮预先明确的解释纪律

1. 重点一起看 EG、VLM、CLC 与 MS/DT，不能只挑一致性或某一个上涨指标。
2. 原始总表包含所有官方指标；没有自行新增加权综合分，也不按自定义歧义标签删官方题目。
3. 若收益小于可见的评分波动、区间跨零、或伴随动作退化，结论写“不确定/有代价”，不据此临时换裁判或调门槛。
4. 当前角色/外观控制器未经完整校准；旧实验候选的 54/57 不能当作本轮控制器准确率。
5. 当前配置含 camera-cut 前缀。为保持与归档 A 的对照，本轮不修改；正式 NarraStream 60 秒协议需另行核对提示切换与切段。
6. 五例属性修复、旧 C 的完整分数都不替代当前 C 的结果。
