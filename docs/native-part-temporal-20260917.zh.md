# 衣服部位提示与时间传播：冻结开发对照

当前任务仍未达到 submission-ready。本实验针对上轮发现的 Clara 衣服区域收缩，只检验定位组件；没有生成修复视频，没有独立质量分数，也没有把任一条件设为生产默认。

## 输入与四种条件

使用已暴露的官方 LongLive-RAG ns310 原始父视频第一个 10 秒镜头，共 160 帧。沿用此前自动获得的人物框、相同 SAM2/CLIPSeg 权重、人物轨迹、0.35 阈值、最多两步扩张、脸部和另一人物的估计保护区域。冻结后一次执行全部条件，未进行参数搜索。

- 文本条件：通用 `clothing`；或从类型化脚本中逐字读取的 `coat` / `jacket`。
- 时间条件：每帧独立 CLIPSeg；或将相应方法在第 0 帧自动生成、排除估计保护区域后的掩码作为 SAM2 mask prompt，向后传播。首帧为空即停止，不挑后续更好帧，不使用人工像素输入。

传播使用两个独立的新 SAM2 状态，分别对应两种文本条件；每个状态同时包含两个人物的部位对象。人物轨迹和后处理由四种条件共用。实际加载的 ViTImageProcessor 直接缩放到 352×352，没有中心裁剪；本次也保留了处理器配置，避免把语义响应问题误归因为这类坐标变换。

固定三帧的工程检查显示：两种修改均减少了 Clara 区域缩成肩部小块的现象，但袖口、手部附近仍有边界误差。`clothing` 还覆盖 Miles 的内层白色衣服，`jacket` 更集中于外层。面积较大、区域非空或时间稳定都不能证明定位准确；所有八组数组仍无像素真值。

脚本衣服名也有局限：当生成内容本来就是错误衣服类型时，搜索期望的 `coat` 可能漏掉实际需要修改的衣服。首帧传播会保留首帧误差，且不能保证遮挡、重新出现或跨镜头有效。当前没有用覆盖率选出“最佳”方法，也没有将它接入首轮修复或自动验收。后续应把时间传播作为有限候选进行更广的开发验证，并检查手部、身份和动作保持；不能直接凭本例宣布净收益。

worker 总用时 95.59 秒：人物 SAM2 跟踪 16.41 秒，两次部位传播为 15.77 / 15.81 秒，五次 CLIPSeg 视频处理另有逐项记录。这些子时间包含在总时间内，不应重复相加；未测量 kernel GPU 时间。新增 VLM 请求为 0，真实 SAM2/CLIPSeg 计算确实执行，新增视频生成和保留改善均为 0。
