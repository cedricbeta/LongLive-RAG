# 类型化脚本编译与原生视觉诊断：开发记录

本轮解决的是脚本要求进入自动诊断的程序边界，尚未证明纠错有效。所有脚本均已用于开发；没有独立留出结果、新增人工标签或正式质量分数。旧编译失败、当前失败和原始回答均保留。

## 类型由原文短语决定

此前 30B 输出虽然通过原文检查，却把 `buzz cut` 当成颜色、把光照动作当成发型。新增有限英语名词短语语法，由末尾名词决定部位和类别：`long tan coat` 产生衣服长度细节、颜色、种类，`buzz cut` 只产生发型。程序保留 `auburn`、`charcoal` 等原文字面值，不按人物姓名补外观，也不把未来才出现的属性提前生效。

v4 仍由模型挑选原文短语。在冻结的 ns090、ns310、ns050 上，实际执行 6 次文本调用，三例均未准备就绪：分别出现非逐字引用、复合描述和动作未拆开、引用含另一人物。一次有界纠正未解决这些问题。

v5 改为程序从原始六段脚本枚举带字符偏移的物理短语，固定候选 ID、原文、类别与值；模型只返回人物表、出现情况及候选归属。归属列表必须覆盖全部候选，不能修改词语或悄悄删除不确定项。明确紧邻的人名主语/所有者发生冲突时拒绝编译。未知修饰词、否定或归属不明项保留为 unresolved，并阻止该编译结果进入生成。

这仍是有限语法：未知名词可能未被枚举，代词和群体归属没有语义正确性保证，场景物品也可能使编译保守停止。`ready_for_development` 只表示通过程序检查；`semantically_validated` 始终为 false。

## schema 传输对照

[已安装服务端和客户端的代码审计](../results/typed_schema_transport_audit/audit.json) 表明：`response_format` 中的 JSON schema 用于约束采样，但不会自动出现在模型读到的消息文本中。新增可选包装器把同一个 schema 追加到真实提示词，并保留原有服务端约束和采样参数。提示词字节进入缓存指纹，不能复用或重命名旧回答。

冻结同一 v5 实现、三个脚本、8B checkpoint、seed=0、最多两次调用/例、无语义纠正循环：

| 开发设置 | 实际文本调用 | worker 秒 | 通过程序检查 | 仍未解决 |
|---|---:|---:|---|---|
| v4 原文短语 | 6 | 41.30 | 无 | 三例 |
| v5 候选归属，schema 仅约束采样 | 3 | 1.00 | 无 | 三例均空人物表 |
| v5 候选归属，schema 同时进入消息 | 5 | 73.64 | ns310、ns050 | ns090 仍空人物表 |

这些是顺序开发记录，不能当作三例独立准确率实验。只有后两行保持编译协议相同。ns310 的 Miles 没有被添加原文未指定的发色；ns050 的 `young men` 从第三号镜头才生效。Iris 的失败未被手工修补。该传输区别不能追溯解释所有历史视觉误判，视觉检查器在本次运行中也没有使用这一包装器。

## 衣服掩码收缩的来源

[真实分解实验](../results/native_multientity_components_v1/run/result.json) 重用上轮自动人物框，在相同 160 帧上重新执行 SAM2 和五次 CLIPSeg 视频分割。四组完整帧掩码逐元素复现；worker 总耗时 61.26 秒，未新调用 VLM，也未生成视频。历史字段 `new_model_calls: 0` 只指新增 VLM 请求，不表示没有模型计算，见同目录的字段说明。

Clara 在第 0/80/159 帧的人物区域为 979/967/991 个网格单元，原始衣服响应为 434/19/5；与人物相交后仍为 434/19/5，与脸部重叠均为零。后两帧扩张后得到 81/45，但扩张并不证明恢复了真实衣服边界。因此本例主要故障出现在逐帧衣服响应，而非人物轨迹消失或脸部排除。

## 两镜头诊断范围

本次另行冻结 ns310 原始父视频、前两个镜头、修复次数 0、前瞻 0 和 600 秒的新工作启动预算，重新调用 v5 编译和真实视觉诊断。运行结果与程序汇总见 [原生诊断](../results/native_typed_diagnosis_v5/run/status.json) 和 [本轮汇总](../results/typed_native_contracts/development_summary.json)。此设置只检查自动入口，不允许新视频生成；未解决项继续计入结果，身份参考不因外观检查而晋升。即使程序运行结束，也不等于整片通过或完成自动纠错。

实际完成两个镜头，worker 用时 500.46 秒，包含 27 次模型调用：2 次文本编译、12 次人物枚举/归属、12 次单帧属性检查、1 次有限联合复核。每个镜头各有 14 个 satisfied 记录；镜头 0 的发型及其汇总记录为 unknown，镜头 1 对应两项为 violated。汇总项和原子项有包含关系，不能相加当独立缺陷数量。镜头 0 的联合复核与单帧负面证据冲突，未被多数通过覆盖；镜头 1 的两个时间点负面回答被保留为检查器冲突。它们都是同一未校准模型的判断，不是独立质量标注。

第二镜头自动产生四个头发区域选项，覆盖 40 个原生 latent。[逐项审计](../results/native_typed_diagnosis_v5/audit/audit.json) 验证了父视频/latent/时间绑定，以及每四帧并集减保护区域的逐元素一致性。但[真实预览](../artifacts/native_typed_diagnosis_v5/native_hair_region_preview.png) 仍显示区域伸出可见头部上沿；估计保护区域零重叠不等于没有损伤风险。原生生成器未被调用，四个选项未被执行。`attempts=1` 指检查原始父分支；`render_budget_exhausted` 是预设零修复次数的停止原因。最终 original/current-best 都仍是原视频，fully-verified 为空，身份参考为空，隔离区保留两个未通过的观察，无不可见记忆泄漏。

相关导出代码通过 [166 项测试和 9 项子测试](../results/typed_native_contracts/exported_tests.txt)，覆盖构造的语法、候选不可修改、schema 提示词缓存、坐标和事务约束，不证明自然语言泛化或视觉准确率。独立评估、真实人工比较、同预算纠错/重试/多次生成对照、正式留出实验及 IAMFlow 权重依赖仍未完成。
