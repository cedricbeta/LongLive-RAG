# 评测、裁判、执行器三层同时修（2026-09-11）

接着 09-10 的 33 场景结果做。那轮的结论是三层误差都大于效应量：裁判色盲且弃权多、
执行器整身重画改了不该改的、评测的 entity_grounding 有随机回落。这一轮四张卡同时开，
每层各修一处，全部先在离线或小样本上验证，再决定要不要重跑 33 场景。

## 评测：entity_grounding 的回落

根因在 NarraStream-Bench 的 `entity_extraction.py`：实体抽取用 planner 模型加
`json_object` 模式，对某些 caption 稳定地回 `{"": ""}`。温度 0 下同一请求重试 10 次结果
一样，10 次之后该段拿 0.5 默认分，而且失败响应不进缓存，下一次评测再掷一次骰子。A 那次
42 段回落、当前 C 那次 20 段，25 个逐字节相同的视频里 10 个 EG 不同，就是这么来的。

修法在审计包装 `scripts/run_audited_narrastream_eval.py` 里，不改外部 checkout：解析器
拒绝一次，下一次重试就在最后一条 user 消息后面追加一段格式提醒（最多 3 级），请求变了缓
存键也变，`api_events.jsonl` 和 `audit.json` 里记 `nudge_level` 和 `nudged_requests`。
`observed_fallbacks` 顺手把 `reason: empty_entities` 也算进去。14 项测试通过。

同时在 GPU 2 上把归档 A 用旧脚本再评一遍（全新缓存，不共享响应），作为"修之前"的噪声
基线（第二遍没跑成：审计的代码哈希检查发现我在它运行中改了脚本，指标算完了但收尾报错，
这是审计该有的行为；后面不再在评测运行中改这个文件）。和 09-09 的 A 评分比：

| 指标 | 逐样本不同 | 最大差 | 平均绝对差 |
|---|---:|---:|---:|
| conditional_adjacent | 1/33 | 0.4 | 0.01 |
| conditional_longrange | 1/33 | 0.5 | 0.01 |
| entity_grounding | 6/33 | 7.4 | 0.60 |
| vlm_score | 0/33 | 0 | 0 |

这一次 42 个回落段和 09-09 完全相同（同一台服务、同样的失败 prompt 是确定的），EG 的
7 个差异段都不是回落，而是打分 VLM 本身的不确定性，单段最多差 7 分。所以 EG 噪声有两
个来源：跨服务会话变化的抽取回落（09-09 的 A 和 C 之间 42 对 20），以及同会话内打分
的抖动（7/198 段）。

修完之后再评 A：第一版提醒里写了"没有实体就回空列表"，模型对 55 个被拒的 prompt 全部
在第一次提醒后就回了合法 JSON，但其中 39 个是空列表（这些 caption 都写着人名），回落
从"解析失败"变成"实体为空"，总数 42 变 39，没有实质改善，而且这一类以前审计根本
不计。去掉这个出口、把 schema 和"每个被点名的人物都要列出"写进提醒后再评：回落 2 段
（1 段空实体、1 段打分响应长度不匹配，后者走的是从不重试的 ValueError 路径），54 次
提醒全部一次成功，entity_grounding 这一项 4 分钟算完（之前带退避睡眠要近一小时），
A 的 EG 从 58.46 到 59.48，涨的就是原来被 0.5 默认分压掉的部分。vlm、CLC、CAC 逐样本
完全不变。

修后再评第二遍，两遍全新缓存，输入逐字节相同：

| 指标 | 逐样本不同 | 最大差 | 平均绝对差 |
|---|---:|---:|---:|
| conditional_adjacent | 5/33 | 1.9 | 0.12 |
| conditional_longrange | 5/33 | 0.5 | 0.04 |
| entity_grounding | 12/33 | 6.7 | 1.07 |
| vlm_score | 3/33 | 0.1 | 0.01 |

回落两遍都是 2 段，EG 的 16 个不同段没有一个是回落，是打分 VLM 在温度 0、种子 0 下
仍有的抖动（sglang 批处理导致）。这就是评测的地板：EG 单场景 ±1 分、极端 ±7 分，
30 场景配对比较的置信区间必须能吞下它；CAC、CLC、vlm 基本稳定。

新脚本 `scripts/compare_eval_runs.py`：`consistency` 模式比两次评测的逐样本、逐段差异和
回落数；`touched` 模式把 A 对 C 的逐段差异按"修过的镜头 / 修复之前的镜头（逐帧相同）/
修复之后被 replay 重生成的镜头 / 没修的场景"分组。在 09-10 的结果上跑一遍：修过的 6 段
EG 变化是 [-12.5, -20.5, 47.5, 0, 43.8, 11.2]，vlm 对"修复之前逐帧相同"的 11 段平均
-25，说明 vlm_score 是整段视频一起打分的，不能按段拆。

## 裁判：颜色否决

新模块 `utils/agent_appearance_color.py`。从 spec 描述里解析发色、发型、衣色、衣物类型
（词表映射到 13 个色系，浅暖色 beige/tan/khaki 单独一类，charcoal 归黑）；用 CLIPSeg
在 crop 上分出 hair / clothing 区域，逐像素按 HSV 归色系，冲突像素占比 ≥ 0.5 就否决。
宽容表按区域分：外套允许 burgundy/navy/moss 在阴影里测成黑，头发不允许"红发测成黑"，
因为那就是 ns090。有参照图时同样测参照，色系远离也否决。它只会把 VLM 的"是"改成"否"。

在 09-05 冻结的校准标签上离线验证（98 个 crop，dev + holdout）：

| 版本 | 坏 crop 抓到 | 好 crop 误报 |
|---|---:|---:|
| 固定条带 + 初版词表 | 0 / 12 | 16 / 86 |
| CLIPSeg 区域 + 修正词表 | 8 / 12 | 0 / 86 |
| 区域分宽容 + 冲突占比 | 12 / 12 | 2 / 86 |

两个误报都是 ns290 baseline 里 Clara 的栗红发，像素上 V 中位数 0.09，和 ns090 的黑发
（0.04-0.13）分不开，标签本身也在边界上。接进 `EvidenceAppearanceComparer` 之上成
`ColorCheckedAppearanceComparer`，demo 里 `--comparer color`，校准脚本里 `--variants color`。
弃权改成 `--uncertain_policy accept_unknown`：只有分配不确定、别的都干净的镜头照常交付，
约束记 unknown，不注册参照。连续性分配器 `--role_localizer indexed`。

校准（GPU 3，indexed 分配，冻结标签，同一套 packet）：

## 新裁判在 33 个 A baseline 上的缺陷初稿

四路只判不修（sparse 分块、color comparer、indexed 分配、弃权记 unknown），两台裁判
服务，约 5 小时。198 个镜头：95 干净、83 外观走样、16 缺席、4 不确定。和 09-09 旧裁判在
同一批视频上的判定交叉：

| 旧 → 新 | 数量 |
|---|---:|
| none → none | 72 |
| none → 走样 | 36 |
| unknown → 走样 | 27 |
| unknown → none | 21 |
| 走样 → 走样 | 14 |
| unknown → 缺席 | 10 |

83 个走样里 74 个来自像素否决，9 个只有 VLM 证据。抽 6 张对照图看，发现三类误报：
参照比较里主色系相同却因其他色系像素过半而否决（ns060 Clara"白 vs 白"）；深色头发在
蓝光下被判成蓝色（ns140 两个男人）；分配错人之后拿错的参照比（ns030 Clara 指到一个
男人）。前两类改了规则：否决要求主色系本身冲突且冲突像素过半，参照比较要求参照主色
占六成以上；头发区域里亮度低的蓝/紫/绿像素归黑。校准集保持 12/12 抓到、2/86 误报，
ns140 的头发全部通过。在全部 baseline crop 上离线重算，像素否决占多数的实体×镜头从
81 降到 54，变化的 23 个正是抽检时怀疑的那些。第三类要靠分配器，这轮不动。

这份初稿的价值是给出了走样的规模：即使按修后的规则，也有 50 个上下的镜头有可测的
外观走样，是 09-09 旧裁判检出数的三倍。对照图在
`videos/benchmark_20260911/baseline_defects_newjudge/defect_sheets/`，建议抽 30 张核对。

C-new 用旧规则已经跑了 10 个场景，全部作废重跑（记录归档在 `archive_first_attempt/`），
两条 lane 分别用 GPU 3 和 GPU 2 的裁判服务。

第二次跑到 10 个场景时又发现一个问题：ns090 六个镜头全被标成 `reject_entity_drift_unmaskable`
隔离，零次修复。属性 mask 减掉脸之后覆盖率回到 1% 以下，裁判用于判断"没东西可修"的
最低覆盖阈值（1%）把它当成无 mask。五例实验脚本没有这道检查所以修得出来。改成属性
mask 的下限单独取 0.2%，只重跑受影响的 3 个场景（ns010、ns030、ns090）和未完成的，
其余 7 个保留。

第三次跑到 23 个场景时 lane 0 停了：ns200 的 edit_shot05 渲染和归档 A 从第 0 个 chunk
就不同（中帧 MAE 从 9.5 一路涨到 86），配置和 15 分钟前那次 edit_shot04 完全一样，而
那一次的前 32 个 chunk 和归档逐像素相同。前缀检查按设计 fail closed，把 lane 0 停了；
lane 1 不受影响跑完了它的 13 个场景，全部前缀检查通过（解码帧基准最大 5.1）。我的进度
监视盯的是旧日志名，18 小时后才发现 lane 0 已死。inductor 缓存目录自 09-02 没动过，
看不出被清；更像一次性的数值不确定事件（怀疑是负载下的 kernel 自动选择）。处理：
后端遇到前缀分歧先重渲一次，第二次仍分歧才判失败；用 ns200 的 baseline 配置重放一次
和归档逐帧比，相同才恢复 lane 0，否则说明归档 A 在这台机器上已不可复现，那就得重新
渲染 baseline 再比。重放结果：384 帧全部逐像素相同（MAE 0）。所以 16:47 那次是一次性
事件，不是缓存或环境变了；lane 0 在 09-12 11:12 恢复，剩 10 个场景，带重渲一次的保护。

| 修复之前的镜头（逐帧相同） | 25 | 0.00 | 0.00 |

20 处修复逐镜头看，收益最大的是 ns180 镜头 0（藏青衬衫改成剧本的深绿，EG +70）和

## 这一轮能说什么

裁判看得见颜色走样了（留出集 9/9，误报 2/86），修复大多只改属性不换人（五例 DINO
0.80-0.99），评测的默认分噪声去掉了（回落 42 → 2）。在这个基础上，闭环在它碰过的片段上
把 vlm_score 提高约 4 分（区间不跨零），EG 提高约 4 分（区间擦零），平滑度略降但不
显著；全集平均只动 1 分以内，因为九成镜头没被碰。还漏的一类是"换了人但颜色对"的修复
被接受（ns190 镜头 2），下一步是 DINO 向后一致性门槛和"三张 crop 任一否决即不通过"，
以及分配器那 3 例。

### 属性级 mask：五例

| 例 | 部位 | 整身 09-06：改对 / 人物外改动 / DINO / 后续镜头改动 | 属性 mask：改对 / 人物外 / 人物内 mask 外 / DINO / 后续 |
|---|---|---|---|
| ns090 | hair | 8/8 / 13.9 / 0.49 / 54 | 4/8 / 7.7 / 21.8 / 0.90 / 43 |
| ns180 | garment | 8/8 / 43.1 / 0.82 / 71 | 8/8 / 28.3 / 70.2 / 0.89 / 56 |
| ns190 | hair | 8/8 / 9.5 / 0.86 / 54 | 8/8 / 7.9 / 10.5 / 0.99 / 45 |
| ns220 | garment | 8/8 / 9.3 / 0.80 / 64 | 8/8 / 9.2 / 54.3 / 0.80 / 49 |
| ns310 | garment | 8/8 / 14.6 / 0.75 / 48 | 8/8 / 8.7 / 42.3 / 0.83 / 45 |

改动量是逐帧像素 MAE（0-255），"人物外"指 SAM2 人物轨迹之外，"人物内 mask 外"指人物轨迹
内、部位 mask 外。DINO 是 baseline 与修后 crop 的余弦，8 帧平均。

三点。第一，外套类三例两种 mask 都把颜色改对，属性 mask 把人物外的改动降了三到四成、
DINO 提高 0.03 到 0.08，但"人物内 mask 外"仍有 40 到 70 的改动，因为外套本来就占人物
大半，加上 mask 膨胀一格（32 像素）和同镜头后续 chunk 的条件传播，头脸也跟着变。第二，
发色类 ns190 是最干净的结果：属性 mask 8/8 改对，DINO 0.99，等于只换了头发，整身重画
虽然也改对但 DINO 掉到 0.86。第三，ns090 的头发 mask 在 latent 网格上只有 0.4-0.6%
（ns190 是 1.1-1.2%），重画出来是头上一块白布，8 个 crop 只有 4 个通过颜色检查；整身重画
则换了一个人（DINO 0.49），还多画出一个花盆。mask 太小时局部重画不可靠，需要最小覆盖
或者膨胀到一个下限。

后续镜头的改动两种 mask 都在 40 到 70，这是 replay 的蝴蝶效应，属性 mask 只略小。

给部位 mask 加了最小覆盖：不足 latent 网格 1% 就在人物轨迹内膨胀一格（最多两格）。
ns090 重跑，头发 mask 从 0.5% 到 1.4%，颜色检查 8/8 通过，DINO 0.79-0.94，人物外改动
8.6。但逐 chunk 看画面，头发是红了，脸上却贴了一张带字的白纸，8 个 chunk 都有。这暴露
两件事：局部重画在头部附近会把文本 prompt 里的"flower shop"之类画成标签；我选的两个
自动指标都没抓到它，颜色检查只看头发，DINO ViT-S/16 的余弦对一张纸遮脸不敏感。于是
部位 mask 再减掉 CLIPSeg 的 "face"，正式裁判里同样处理（`part_min_coverage=0.01`，
排除 face）。ns090 排除脸后重跑：头发 mask 回到 0.4-0.7%（膨胀进脸的部分被减掉），
颜色检查 8/8，DINO 0.86-0.996，人物外改动 9.6，逐 chunk 看头发变成浅红棕、脸和人
都是原来的，没有贴纸。这一例三个版本并排：

是换了个人。这只是五例、单种子、机器指标，不是成功率。
