# 投稿实验协议：用公平的定量比较验证长视频纠错

修订：2026-09-17。**设计协议，尚未冻结正式测试、未产生新成绩。** 本次只重写 goal 和实验方案，不改 submission 正文。原论文表格、流程、数字和来源见 [逐表核对](paper-table-audit-20260917.zh.md)，交付要求见 [goal](submission-goal-20260917.zh.md)。

## 1. 需要证明的主张

在已有长视频记忆方法之上，**相同实际推理预算下，降低最终实体约束错误，同时保留身份、动作、画质和后续内容**。

LongLive 已有流式生成与 recache；LongLive-RAG/MemFlow/IAMFlow 已有历史或身份记忆；VideoRepair 已有检测、规划与局部纠错。贡献不能只是多一个 VLM、mask、重画或提示词。候选贡献是：累积可验证的局部改善，从一致的生成状态继续修复，将未核验内容与可信身份记忆分开，并在质量—成本上优于替代策略。以下五张实验表决定这些主张是否成立。

## 2. 三类公平比较

| 比较 | 固定条件 | 能支持的结论 |
|---|---|---|
| 官方系统重评 | 同一数据、长度、输入可见性、评测器和硬件预算；保留各系统核心机制 | 系统的最终质量/成本差异；不同 checkpoint 的差异不归因于某个模块 |
| 同生成器开关 | 同 checkpoint、精度、VAE、调度、初始视频及状态；只改变纠错 | 纠错的因果增益 |
| 同预算策略比较 | 上述配对条件，加相同额外资源上限、同等开发调参预算、独立最终评分 | 是否优于重试、重生成与已有纠错 |

同参数量不等于同 checkpoint，相同 seed 数字不保证跨实现使用相同噪声。修复前后配对依靠保存的原始分支。单次 baseline 只是质量/成本起点，不能作为大量额外计算后的唯一对手。

### 2.1 方法身份与复现

| 方法 | 必须保留的机制 | 主要用途 |
|---|---|---|
| 官方 LongLive 1.3B | checkpoint、sink/local、KV recache | 原生锚点 |
| 官方 LongLive-RAG on LongLive 1.3B | base+LoRA+训练后的 AE、检索与窗口预算 | 单提示词原协议；叙事任务标多提示词适配 |
| 官方 MemFlow 1.3B | 训练后权重、NAM、SMA | IAMFlow 的直接 backbone 对照 |
| 官方 IAMFlow 1.3B | MemFlow 系权重、ID memory、LLM/VLM、APT、实际精度/VAE | 强记忆对照 |
| 对应 backbone + Ours | 同生成器、同初始分支、相同恢复方式 | 主要为 RAG±Ours、IAMFlow±Ours；LongLive 作辅助 |
| VideoRepair 长视频适配 | 检测、正确区域保留、局部提示、候选筛选等核心流程 | 直接纠错竞争方法 |

本地旧 A=5B 原生路径、B=内部 KV-RAG、C=历史实体路线，均不能改名为官方 RAG/IAMFlow。5B 单列规模实验。IAMFlow 未运行时保持“未完成”；MemFlow 的结果不能代替 IAMFlow 的成绩。

每个 baseline manifest 记录代码 commit/patch、权重/LoRA/AE 哈希、steps、精度、VAE、sink/local/retrieval 的实际 latent-frame/token 容量、FPS、帧数、种子、提示发布时间、LLM/VLM 和设备分布。另列 `paper reported / our reproduced / difference / protocol deviation`；论文引用值不得混进统一重评主表。

已核对的复现陷阱：

- RAG 原表总窗口为 12；公开 yaml 的 `num_output_frames` 是 latent 计数，120 不直接等于 120 秒。
- IAMFlow 论文速度配置含 TinyVAE、异步解码、FP8、双 H20；公开默认 yaml 关闭前两项。先核验入口覆盖和论文质量/速度配置，不能拼接不同设置的成绩。
- LongLive 单 H100 FPS、IAMFlow block FPS/双 H20 E2E、RAG retrieval-only 490ms 是不同测量，不能直接排名。
- 保留官方容量的系统比较，与统一容量的机制实验分开。统一容量或精度时明确标为受控改编，不删除 baseline 核心机制。

RAG 多提示词适配对 native/RAG 使用相同时间表和正确 recache。纠错需要一致维护 latent、KV、文本条件、随机状态、检索与身份状态；若 replay 重建，全部计成本。OFF/zero-mask、前缀保持、非零编辑进入后续生成是最低工程验收，通过不代表视觉收益。

## 3. 数据、信息与样本量

### 3.1 NarraStream-Bench：60 秒主任务

官方全量 324 条，6×10 秒，832×480；由 12 scenes×9 blueprints×3 variants 构成。这是单场景叙事多提示词任务，不能擅自加入“切镜头”或独立生成六段。按真实解码时间核验切换、帧数、FPS；不能改 MP4 FPS 伪装长片。

两个报告层必须分别标注：

1. **公开基准层**：全部 324 条，首轮固定生成 seed 0，七个 T1 主表行全覆盖。披露开发重叠，不称独立留出集。
2. **确认层**：方法冻结前，以模板组划分未暴露的脚本，固定 seeds 0/1/2；关键对照共用清单。规模根据开发方差和目标效应估算，在看结果前冻结。可复用同配置 seed 0 原片，不能选择性复用成功输出。

建立完整暴露清单，包含旧 33 条、Iris/Clara、所有后续人工检查/调参案例及共享 scene/blueprint/entity 模板。不能默认余下 291 条独立。公开池不足时，冻结外部新模板确认集；其成绩不与原文 324 总分混用。

主任务为**脚本预先给定的离线生成/纠错**：所有方法可访问相同完整脚本，保留其官方按段调用方式。H=2 可查看后续生成片段，但必须按离线/延迟交付计成本。若声称在线能力，另做 prefix-only 轨道，逐段发布提示、禁止偷看未来，报告交付延迟。当前 replay 不支持实时主张。

自动方法只获得原文和自身历史，不给 Ours 额外人工属性、mask、参考图或错误位置。自动提取约束属于方法，计成本并审计漏检；最终评测要求独立固定，不能用 Ours 漏掉的要求定义分母。人工 oracle 单列上限。

### 3.2 MovieGenBench：单提示词长度扩展

采用 RAG 发布的 128 条固定 refined prompts，所有方法用同一文件哈希，不分别润色。保留 **30/60/120 秒**三个长度，第一轮固定 seed 0；多 seed 确认范围另登记。

全量主表不能根据修复效果筛选。人物/非人物等子集在生成前按文本定义；不适用样本的 abstain/开销仍进入全量报告。生成后按原片错误分层的结果标为条件分析。

LongLive 的 160 条 interactive、MemFlow 的 100 条、标准 VBench-Long suite 与上述数据不相同。获得确切原数据/脚本才称原表复现；自建相似数据不叫复现。

|---|---|---|---|---|---|---|---|---|---|---|
| 每个固定方法一行 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 |

|---|---|---|---|---|---|---|---|---|---|---|
| 每方法、每长度一行 | 30/60/120s | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 |

最低完整 block 为 LongLive、LongLive+RAG、LongLive+Ours、LongLive+RAG+Ours；其他 backbone 按泛化主张增加。这里的 LongLive 是关闭 RAG 的同一 base+LoRA，若与另一个官方 LongLive release 权重不同，必须在行名注明 matched base；不能只凭名称相同当作同 checkpoint。使用官方长视频切片与 slow/fast 聚合；不能把 60 个切片当作 60 条独立视频。

### T3：同预算下是否比多试几次有效

各策略共享未经结果筛选的原始视频池；先在官方 RAG 跑通，再在 IAMFlow 验证。

| 策略 | 固定行为 | 排除的替代解释 |
|---|---|---|
| Native | 单次生成 | 基础质量/成本 |
| Best-of-N | 原片加额外完整采样，冻结选择器选择 | 更多完整采样即可解释收益 |
| 固定局部重试 | 同 detector、初始范围/提示/验收；只换噪声 | 局部重采样已足够 |
| Prompt-only feedback | 同等规划，改提示后重生成，无局部状态保留 | 收益只来自更清晰文本 |
| VideoRepair 长视频适配 | 核心检测/保留区/局部提示/候选选择 | 已有纠错已足够 |
| 完整 Ours | 冻结的渐进保留、有限反馈和后续验收 | 新机制的增量价值 |

VideoRepair 原设置为 K=5 候选、一次 refinement。先做原方法设置检查，再提供预算受限适配；预算不足采满五个时明确标注。替换 GPT-4o、分割器或双路生成必须记录偏差，并另给共享模块受控版本。只复刻部分机制称 VideoRepair-style，不能称官方复现。

预算以开发测得的同 backbone 单片成本 C0 为单位，先检查**额外 0.5C0/1C0/2C0**三档是否可执行，再转为具体固定 GPU-seconds 冻结。每策略同等上限；低档不足以完成整片候选时，Best-of-N 保留原片，报告候选数及未用预算。不可中断动作使用相同预留/超支规则，实际超支不隐瞒。

全成本包含生成、观察、分割、规划、候选、选择、后续检查、replay；共享初片成本在各系统总账计一次。并发 GPU 按各设备占用时间求和，墙钟另报；不同 GPU 型号的秒数不能直接视为等价。远程 API 单列模型、调用、tokens、费用、延迟并匹配配额，不能以 GPU-s 掩盖额外 API。最终离线评价成本单列，不计入生成 FPS。

表列 final error burden、EG、修复率、新错误率、候选数、真实成本、交付率，画质量—成本曲线。选择器不能用最终测试评分；所有可用原片/候选按预定规则参与。各策略享有相同开发调参预算，正式阶段不能手选版本。

### T4：机制消融与后续影响

同 backbone、同原片、同预算，并覆盖多属性错误；否则无法验证渐进修复。

| 消融 | 唯一主要改变 | 主要观察 |
|---|---|---|
| 一次 vs 渐进修复 | 修复轮数 | 每轮/最终净错误、成本 |
| 全通过才保留 vs 部分改善保留 | 分支保留规则 | 被丢弃的真实改善、累计错误 |
| 固定重试 vs 反馈 | 动作策略 | 等预算净修复、重复动作率 |
| 整段 vs 自动局部 | 范围 | 目标成功、身份/动作、新错误 |
| 当前验收 vs +H=2 | 后续检查 | 后续两段及全片尾部退化、成本 |
| 无回退 vs 父分支+原始锚点 | 接受规则 | 新错误、误拒绝、最终错误 |
| 直接写记忆 vs 隔离未核验身份 | 记忆写入 | 后续身份污染、错误持续时间 |

不能一次同时换 prompt、mask、seed 策略和 judge。Oracle 错误标签/mask/参考只作上限；工程单测和 zero-mask 不放有效性主表。

### T5：独立评价、效率与失败

独立 judge 面板：固定视频、证据帧、问题、聚合，仅替换成不同模型家族，报告 EG/CLC/VLM、错误审计、分歧和覆盖率。生成端 verifier 不作最终真值；更大的同家族模型不等于独立模型。

人工面板：冻结后随机分层抽样，建议起点 60 条、每条至少 3 人；实际规模按开发噪声确定，不把 60 当功效保证。隐藏方法名、随机左右、允许平局，展示同一脚本、同步全片与后续内容。评价目标、身份/动作/非目标保持、整体偏好，记录一致性。false accept/false reject 要同时抽查接受/拒绝候选。没有实际标注者就保持待完成。

效率面板：列硬件、精度、steps、VAE、并发方式，报告 warm E2E p50/p95、实际帧数/E2E、block FPS、总 GPU-s、每卡峰值显存、API、失败/超时/回退率。冷启动单列。质量与速度来自同一配置或明确分行。

## 5. 独立纠错指标及 unknown

以**脚本×实体×约束×预定时间窗口**为单位，从原始要求和独立标注规则确定评测约束。合理换衣、光照变化、离场不当漂移。原片缺陷在不知道候选结果时标注；目标窗、后续再次出现窗和尾部窗事前固定，不能只取好帧。

设原片确认错误集 F0、确认正确集 P0、预定约束数 N；C 为 F0 中最终确认正确且通过保护的数量，A 为 P0 中最终确认错误的数量：

- **确认修复率** = C/|F0|。遮住目标、删除人物、换人或 unknown 不算修好。
- **新错误率** = A/|P0|；另报 P→U，不能把变得看不清当保持成功。
- **最终错误负担** = Ffinal/N；同时报 Ufinal/N 和保守未解决负担 (Ffinal+Ufinal)/N；unknown 做最好/最坏界。
- **净修复量** = (C−A)/N，必须与最终错误/unknown 同看。
- **后续持续性**：原片预定目标在后续出现窗仍正确的比例、再犯率、错误持续时间、后续非目标新增错误。
- **触发与交付**：全体视频的触发、正确原片误编辑、超时、执行失败、回退率。退回原片为零修复增益。

每脚本先算，再宏平均，另给 micro counts 与缺陷分类；零分母记 N/A 并公布适用脚本数，不填 100%。face/CLIP/DINO embedding 只作辅助；改变目标发色不能自动判换人，embedding 相似也不等于身份已认证。

## 6. 定量目标与正式判据

下列是**项目提出的开发目标，尚未验证**，不是论文已有成绩。用开发重复性、方差、人工可觉察变化与算力校准一次；正式冻结前记录最终值和理由，不能看过测试后放宽。

| 目标 | 初始规划值 | 确认方式 |
|---|---|---|
| 实质纠错 | 最终确认错误负担相对下降 ≥15%，同时给绝对百分点 | 配对差值 CI 上界 <0；unknown/保守负担不恶化 |
| 官方指标对应改善 | EG +2 分或以上，0–100 尺度 | CI 下界 >0；内部接受率不能代替 |
| 整体质量保留 | Overall 下降≤0.5 分；预定关键质量项≤1 分；DD≤2 分 | 各保护项非劣检验；不显著不等于无退化 |
| 保护原正确内容 | 新错误率≤1%，P→U 不上升 | 上置信界支持；样本不足不能宣称达标 |
| 反馈决策必要 | 同预算赢固定重试、Best-of-N、直接纠错对照 | 预定主预算档位，初始额外 1C0，净错误差值 CI 支持 |
| 人眼确认 | 胜+0.5×平 的偏好率>50% | 脚本聚类 CI 下界>50%，同时核对目标和保护 |

质量/动作保护项固定为 NarraStream 的 SC/BC/TF/MS/VTSS/BS/CAC/CLC/DT/VLM，以及单提示词的 SC/BC/MS/AQ/IQ；DD 使用单独界限，不能看到哪项下降再把它移出保护集合。

主要比较预注册为 RAG±Ours、IAMFlow±Ours 的 EG 和最终错误负担。模板分组、脚本配对，多 seeds 在脚本内先聚合；10,000 次分组配对 bootstrap，固定统计 RNG。共享 scene/blueprint 时做更高层聚类或双因素敏感性，公布有效组数。帧、切片、seeds 不能当独立 N。主要比较用 Holm 或预定层级检验；其余标探索性。

上表目标效应的点估计与“有正向证据”分开报告；若论文声称“至少减少 15%”或“至少增加 2 分”，区间也必须支持该下限，不能仅凭点估计达标。非劣界限必须事前冻结。

区分分数/百分点与相对百分比；原始 [0,1] 统一尺度后计算，最后才舍入。bootstrap 不会修复开发泄漏或有偏 judge。

所有原生生成失败、执行失败、解析失败、API 超时均保留。能交付原片时按实际回退版评分并标失败；无完整输出记 missing，另给按尺度下界计入的失败敏感性结果，不冒充官方评分。valid-only 官方均值必须与全体交付率同报，不能按方法各自删难例。

| 实际证据 | 允许结论 |
|---|---|
| 两个官方记忆系统的确认层均有 EG/净错误收益，保护成立，赢预算对照 | 已测系统和约束上的可迁移长视频纠错 |
| 只赢单次 baseline | 质量—计算折中；未证明反馈优于更多采样 |
| 只赢发色等子类 | 该子类修复；不宣称全部实体/动作 |
| 只总分升，EG/独立错误未改善 | 核心实体纠错主张未成立 |
| 只有精选视频、接受数、工程检查 | 开发证据，不能支持主结论 |

## 7. 执行顺序与预算门槛

**P0 复现核对。** 完成 baseline manifest、权重访问、真实时长、OFF/zero-mask、评测缓存和全指标检查。已有官方 RAG 适配不从零重做；补缺口。IAMFlow 获取受阻时继续 RAG，不造替代成绩。

**P1 有界开发 pilot。** 从已暴露池事前选 12 条覆盖缺陷/无缺陷的脚本，1 seed、60 秒；跑 native、固定局部重试、Best-of-N、完整 Ours，统一预算。看独立错误、EG、质量和成本，不在同一 Iris 上无限改检查提示词。若固定重试解释收益，先改方法或收窄主张，不只加循环。pilot 不作为确认性检验。

**P2 冻结。** 交付方法/配置 commit、暴露清单、数据哈希、预算秒数、主要终点、保护界限、抽样/聚类/检验、异常处理及总规模。T1 全量 324×7×1 seed=2,268 个系统输出；T2 四行×128×3 时长=1,536 个输出。成对方法可复用初片，但额外生成/评测计费；确认层、T3/T4、人工另算。若算力不足，结果出来前缩小方案并收窄结论，不能拿少数视频外推整套成本。

**P3 正式实验。** 先 T1 关键配对与 T3 主预算，再 T2 长度、T4/T5。正式 bug 修复保留旧版和失败，统一重跑受影响方法，不能只重跑输了的 Ours。每张表由机器记录生成，能追到样本/视频/方法/评分版本与成本。

**P4 投稿材料。** 以方法、主表、机制、成本、局限组织正文计划。病例流水账、schema 调试、逐轮解释归附录/复现目录。成功图要对应主表样本，给同脚本/时间点、baseline/最好预算对照/Ours、mask与后续；另固定抽样普通/失败案例。精选视频不给成功率，不能替代 T1–T5。
