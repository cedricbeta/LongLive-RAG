# C 阶段：离线部分改善事务与父 latent 重放

这是开发实现，不是已验证的视频质量结果。真实 Iris 试运行在
`videos/progressive_repair_20260917/iris_progressive_c_probe`，其 manifest
冻结输入、源码、首镜头处理范围、最多两个候选和最多两个后续镜头。
结果完成前不得称为成功修复。该案例已用于开发，不属于独立留出集。

## 实际行为

入口为 `scripts/run_agent_edit_demo.py --repair_policy progressive --judge entity
--comparer attributes --attribute_masks --entry_sigma 1.0`。默认 legacy 路径不变。

1. 保存每个父分支的完整 clean latent、视频和内容哈希。mask 带来源视频哈希、
   帧数、网格和 chunk 范围；来源不一致即拒绝运行。父分支变化后检查器重新定位。
2. 重放时在当前镜头的每个编辑前取父 clean latent，在严格前缀的 clean recache 前
   取父 clean latent。修复后 latent 进入正常 recache 和后续生成。先前修复不用旧
   prompt 再执行一遍；历史动作保存在分支图。修复后的 recache 显式恢复原脚本文本。
3. 只有明确的目标 fail→pass 才能成为改善。原有 pass 退化、要求定义变化、目标
   变得不可观察以及身份/动作等关键 unknown 都阻止接纳。剩余旧错误不会仅因其
   仍然存在而否决已确认改善，也不会从评测分母中消失。
4. 成对保护调用看父版本、候选、固定原始版本、脚本及已有可信参考，检查身份、
   其他角色、非目标属性、动作、场景和画质；不提供规划者的成功解释。未知证据
   阻止接纳和额外噪声重试。最多 H 个后续镜头重复相对检查与视觉保护。
5. 部分改善成为下一次编辑的父分支，但其身份注册状态回到判断前，payload 留在
   quarantine。完整通过路径、当前最好路径分离；失败候选不覆盖当前最好路径。
6. 每个父版本/实际 mask 张量/提示词组合最多尝试两种噪声；sigma 固定为 1。
   当前只是固定配方控制，不是 D 阶段的反馈动作方法。记录实际 seed、成本、
   父子分支、未解决项、停止原因和执行异常。预算到达后不启动新操作；在途操作
   完成后退出，外层运行器另设硬超时并终止其自己创建的进程组。

## 恢复语义和边界

本实现重建 KV、文本缓存、随机序列和检索状态，而不是把整个 GPU 状态序列化。
重建依赖固定配置、种子、模型与完整前缀；保存的父 latent 保证进入 recache 的
前缀及编辑背景值一致。执行器检查严格前缀 latent 的逐 chunk 哈希。尚未验证
全部 KV/RNG/检索张量逐位相等，不能声称实现了精确状态快照或实时流式恢复。

原始视频是固定比较锚点，不是正确身份的真值。未知首见身份不得被它自动认证。
保护调用只看三个采样帧；动作理解尤其受限。属性检查和保护调用使用同一
Qwen3-VL-8B，不构成独立模型验证。后续检查是有限范围，不能保证全片。

目前接口只支持 hair/garment 的已确认属性缺陷，没有补齐缺失主体、动作修复、
官方 1.3B LongLive-RAG 或 IAMFlow 的编辑适配。5B 开发结果不能证明跨系统收益。

## 验证

`tests/test_agent_progressive_repair.py` 的九项测试覆盖真实目标改善条件、固定锚点、
父 latent 注入、mask 来源与坐标、部分改善继续编辑、失败子分支回退、可信记忆
隔离、完整通过、未知保护停止、执行异常及后续动作损坏否决。测试使用合成
渲染输出，只证明控制与数据接口，不证明视频质量。

相关套件在 Python 3.12 / Torch 2.9 / FlashAttention 2.8.3 隔离环境通过：
113 tests + 9 subtests。旧 Python 3.10 环境的三项内核测试因缺少
`torch.nn.attention` 失败；没有通过跳过这些测试来获得绿色结果。

成本估计、冻结留出协议、同预算控制、独立评分、人工评价及论文。
