# 修复范围可视化与重复动作控制

## 这次修什么

Iris 第 3 镜头的归档记录中，规划模型连续三次输出同一遮罩、同一 caption 和 sigma 1.0，但每次都写“将头发纠正为红色”。v1 只给出一个区域文件，规划者看不到实际覆盖范围，也没有程序检查它所声称的改变。

当前工作区的 `--repair_policy feedback` 已接入以下修改；9 月 14 日的冻结源码和比较结果仍代表旧版本。

1. **实际范围可见**：每个选项附带原片全景、局部放大和遮罩叠加图。红色表示重画权重；具备保护遮罩时，蓝色表示识别出的脸部及其他人物。图片写明绝对帧号，图片、遮罩和原视频哈希进入输入审计。
2. **有不同的范围可选**：属性修复沿用 SAM2 人物轮廓和 CLIPSeg 部位分割，提供原范围、扩一格范围、降低部位阈值到 0.20 的范围。全部在修复前画面上计算，限制在相应人物轮廓内，并排除检测出的脸部和其他人物。相同张量的选项去重，最多提供六个。没有有效属性分割时仍使用已有整人、补位或整镜头范围，不声称这些路径都能提供三种选项。
3. **减少照抄默认答案**：模型看到选项用途、目标、覆盖率、预览图和固定力度，不再在每个选项里收到程序预填的 caption 和 reason。历史中仍保留真正执行过的操作。
4. **检查实际变化**：模型明确返回 `revise`、`resample` 或 `stop`。程序比较遮罩内容及规范化后的 caption；只修改解释、大小写、空格、标点，不能算新方案。同一方案可执行首次尝试和一次明确标注的重新抽样，第三次会被拒绝。模型可再提交一次合法方案；仍无合法方案则结束该镜头并交付修复前版本，标记未解决。
5. **力度固定为 1.0**。明确判为证据不足的失败会停止重画。当前没有实现自动补帧复核；也没有改动旧版对未知人物分配的接受规则。

## 验证边界

CPU 测试覆盖：不同区域确实包含不同像素、脸部和邻近人物排除、遮罩坐标与原片一致、帧号对应、张量去重、预览与时间范围审计、相同动作不能靠文件别名或文字说明绕过检查、一次重新抽样上限、证据不足停止，以及原有回退、前瞻和比较功能。

这次完成的是接口和循环修正。新范围能否让真实模型修好 Iris，需要实际渲染对照。分割模型仍可能漏掉头发或把头发错分为脸；有限的范围选项无法保证解决这些错误。改变 caption 的措辞也不保证产生有效的视觉改变，程序只能检查可执行参数的变化，最终仍须验收画面。

下一步实验应先固定原片、caption、sigma 1.0 和随机种子，只比较范围，然后再评估规划模型能否根据反馈选择更有效的范围。这样才能区分执行器有没有可用的修复方案，以及规划模型会不会选择。
